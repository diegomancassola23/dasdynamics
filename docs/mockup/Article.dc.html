Caching display methods on forms

Cache the display methods your users see on screen, and only those. A cached method is computed for every record at fetch time, visible or not.

First written
29 Jan 2014
Follow-up

Re-read

In D365FO today

You no longer register the method in the datasource’s init(). Put an attribute on the display method itself and the form caches it.

[SysClientCacheDataMethodAttribute(true)]
public display Name customerName()
{
    return CustTable::find(this.CustAccount).name();
}

The 2016 warning still holds: cache only what sits in the grid or on the first tab.

The original note

2014 and 2016 posts, merged and lightly edited

A typical performance tip is to put display methods in the datasource cache, with a call like this in the datasource’s init():

public void init()
{
    super();
    this.cacheAddMethod(tableMethodStr(CustTable, Name));
}

Pay attention: every cached method is evaluated when the data is fetched from the database. Put one on a tab that is hidden when the form opens and it still runs for every record at startup. If the method is heavy, the form gets slow.

Leave it out of the cache and it runs only when its control appears. So cache a method only when its control is visible in the main grid or on the main tab; anywhere else, measure first.

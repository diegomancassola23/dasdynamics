In many real-world implementations of Microsoft Dynamics 365 Finance & Operations, testing warehouse labels quickly and efficiently can become unnecessarily complex.

When working with ZPL (Zebra Programming Language) labels, developers and functional consultants often need a fast way to preview the output generated by the system. However, the traditional approach typically requires installing virtual printers locally — a process that can be cumbersome, time-consuming, and impractical, especially when you simply need to perform a quick validation during development or troubleshooting.

To address this need, I developed a lightweight utility that allows you to preview ZPL labels directly within D365FO, without requiring any local virtual printer installation.

This tool was created specifically to enable fast consultation of label output during development and testing phases. It is not intended to replace Microsoft’s native and recommended tools, which remain the appropriate choice for more complex, production-ready scenarios.

From a technical perspective, the solution leverages the Labelary API ([https://labelary.com/service.html](https://labelary.com/service.html)). While the free version of the service comes with certain limitations, it is perfectly suitable for development and testing purposes.

## How It Works – Screens Overview

### 1. Creating the Virtual Printer

The first step consists of creating a new virtual printer from the organization printers.

1. Navigate to **Organization administration > Setup > Network printers**
2. Select the **Initialize ZPL printer**
3. You can insert the name of the printer and label size

![Virtual printer creation](/images/articles/virtual-zpl-printer-d365fo/image-01.png)

_Virtual printer creation_

At the end a new printer will be created

![Virtual printer created](/images/articles/virtual-zpl-printer-d365fo/image-02.png)

_Virtual printer created_

Using the **Label Printers** button on **Warehouse Management** (an extension button on network printers form) you can see the printer details on WHS settings table.

![Details of printer](/images/articles/virtual-zpl-printer-d365fo/image-03.png)

_Details of printer_

Each time a label is printed using the virtual printer a new record is created on **Label History.** Here you can see of course the preview, the core of this implementation, and the ZPL raw code.

![Preview of label](/images/articles/virtual-zpl-printer-d365fo/image-04.png)

_Preview of label_

### Diagnostics Mode

An additional useful feature is the **Diagnostics flag**, which can also be activated for all ZPL printers — not only for the virtual preview printer. When the Diagnostics option is enabled a record is created in the Label History and the raw ZPL code is stored. No preview rendering is generated in this case

This has two important advantages:

1. It avoids consuming free API requests from Labelary
2. It still provides immediate access to the generated ZPL for troubleshooting on production

In short, you can use the virtual ZPL printer to get a preview of the label, and diagnostic if you need only the ZPL
